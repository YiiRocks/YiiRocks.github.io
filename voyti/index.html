YiiRocks/Voyti

войти — /vɐjˈtʲi/ — verb — "to enter" or "to log in"

Installation · Quick Start · Configuration · Routes · Console · Middleware · RBAC · Social Auth · Views

voyti is a highly customizable user management, authentication, and authorization extension for Yii Framework 3, ported from 2amigos/yii2-usuario and rebuilt with PSR-15 middleware, PSR-11 DI, ActiveRecord entities, FormModel forms, and yiisoft/rbac.

Installation

composer require yiirocks/voyti

Optional packages:

composer require yiirocks/recaptcha
composer require chillerlan/php-authenticator chillerlan/php-qrcode

Quick Start

1. Wire migrations in the host app

Voyti exposes its migration defaults in the package-specific voyti-migration config group. In your application, merge that into the console migration service: 

// config/di-console.php
use Yiisoft\Db\Migration\Service\MigrationService;

return [
    MigrationService::class => [
        'class' => MigrationService::class,
        'setNewMigrationPath()' => [$config->get('voyti-migration')['newMigrationPath']],
        'setSourcePaths()' => [$config->get('voyti-migration')['sourcePaths']],
    ],
];

One migration creates the user, user_profile, user_social_account, user_token, and user_session_history tables with all columns (2FA, GDPR, password expiration, last login IP, etc.) included. Run: 

./yii migrate:up

2. Configure the module (optional)

Sensible defaults are auto-registered via the Yii3 config plugin — no manual setup required. To customize, override the yiirocks/voyti key in config/params.php: 

return [
    'yiirocks/voyti' => [
        'enableTwoFactorAuthentication' => true,
        'enableGdprCompliance' => true,
        'maxPasswordAge' => 90,
        'enableRestApi' => true,
    ],
];

Values set here are merged with the built-in defaults from ModuleConfig::defaults().

3. Register routes

The package exposes its routes under the voyti-routes config group. In your application's router DI definition, include them alongside your own routes: 

// config/common/di/router.php
use Yiisoft\Config\Config;
use Yiisoft\Definitions\DynamicReference;
use Yiisoft\Router\Group;
use Yiisoft\Router\RouteCollection;
use Yiisoft\Router\RouteCollectionInterface;
use Yiisoft\Router\RouteCollector;

/** @var Config $config */

return [
    RouteCollectionInterface::class => [
        'class' => RouteCollection::class,
        '__construct()' => [
            'collector' => DynamicReference::to(
                static fn() => (new RouteCollector())->addRoute(
                    Group::create('/')
                        ->routes(...[
                            ...$config->get("routes"),
                            Group::create('user/')
                                ->routes(...$config->get("voyti-routes"))
                        ],
                    ),
                ),
            ),
        ],
    ],
];

Routes are available at URLs like /login, /register, /settings, etc. REST API routes (under /api/v1) are enabled when enableRestApi is true.

4. Done

DI bindings, event listeners, and console commands are all auto-registered via the config plugin.

Configuration

Override the yiirocks/voyti key in config/params.php. Only the options you want to change need to be specified — they are merged with the built-in defaults from ModuleConfig::defaults(): 

return [
    'yiirocks/voyti' => [
        'enableTwoFactorAuthentication' => true,
        'enableGdprCompliance' => true,
        'maxPasswordAge' => 90,
    ],
];

Middleware

Three PSR-15 middleware classes for access control:

Middleware Description
AccessRuleMiddleware Redirects guests to loginPath; checks administratorPermissionName for admin access
PasswordAgeEnforceMiddleware Redirects to accountSettingsPath when maxPasswordAge is exceeded
TwoFactorAuthenticationEnforceMiddleware Redirects to accountSettingsPath when required permissions are assigned

Both redirect targets are configurable in ModuleConfig, so you can map them to your own route structure. Register them in your application's middleware pipeline as needed.

RBAC Management

Built on yiisoft/rbac. The extension provides a full admin UI for managing permissions, roles, and rules with parent-child hierarchy support, assignment management, and filtering. Default roles are configured in config/rbac.php: 

return [
    'rbac' => [
        'guest' => [],
        'user' => [],
        'admin' => [],
    ],
];

Social Authentication

Nine built-in auth clients:

  • Facebook, GitHub, Google, Keycloak
  • LinkedIn, Microsoft365, Twitter, VKontakte, Yandex

Each implements the auth client interface and maps provider attributes to the SocialNetworkAccount entity. The service layer handles account lookup, creation, linking, and user login.

Events & Listeners

Voyti dispatches events at key points in the user lifecycle, allowing your application to react, log, or extend behaviour:

Event When
UserRegisteredEventA new user signs up
UserLoggedInEventUser successfully logs in
UserLoggedOutEventUser logs out
UserConfirmedEventEmail address is confirmed
UserUpdatedEventProfile or account is updated
UserDeletedEventUser account is deleted
UserProfileUpdatedEventProfile fields are changed
UserPasswordChangedEventPassword is updated
UserSessionsTerminatedEventActive sessions are terminated
SocialAccountConnectedEventSocial account is linked
SocialAccountDisconnectedEventSocial account is unlinked

Four listeners are registered by default: mail notifications for confirmation, recovery, re-confirmation, and GDPR admin alerts. Attach additional listeners via the Yii3 event dispatcher configuration.

Views

Web Views

Web views are in src/resources/views/bootstrap5/. Override them by setting viewPath in config/params.php: 

return [
    'yiirocks/voyti' => [
        'viewPath' => '/path/to/your/custom/views',
    ],
];

Mail Views

Mail templates are in src/resources/mail/ — separate from web views so they can be overridden independently via mailPath: 

return [
    'yiirocks/voyti' => [
        'mailPath' => '/path/to/your/custom/mail',
    ],
];
