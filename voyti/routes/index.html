The library does not provide a menu model or navigation contract. It only exposes named routes that the host application can use in its own menu, sidebar, or access rules.

The routes below are the core distribution's. Two-factor routes are not among them - they are contributed by the separate yiirocks/voyti-2fa packages and are listed in their own table further down. See Two-Factor Authentication for the mechanism.

Two-factor routes (from yiirocks/voyti-2fa)

These register only when yiirocks/voyti-2fa is installed. The base package contributes the confirmation step and the generic settings routes; each method package adds its own setup route(s) via twoFactorMethodRoutes (spliced into the settings/ group).

REST API

The REST API routes below live in their own voyti-routes-api config group (see Quick Start), separate from voyti-routes above - pull that group into your router too if you want the API exposed, and mount it at whatever prefix you like. See REST API for the remaining config options.

Route name Method Path Purpose
voyti/api-openapiGETopenapi.jsonOpenAPI 3.1 spec (JSON). Public, so tooling (Swagger UI, codegen) can fetch it without a Bearer token.

voyti/api-v1-users-viewGETv1/users/{id}View a user

voyti/api-v1-users-updatePATCHv1/users/{id}Update a user
